# 文書の構造と分割

## 原則

- **目的と読者で分ける**。利用者の操作、開発者の保守、調査の採否、実験の再実行は別の文書です。
- サイズは UTF-8 のバイト数で判定します。文字数・行数では判断しません。
- **20,000 バイト超**: 意味単位での分割を検討します（CI は警告のみ）。
- **40,000 バイト超**: 分割、または理由付き例外が必須です（CI は失敗）。
- 分割後は、親の索引（README.md、RESEARCH.md、docs/*/README.md など）からリンクします。索引にない孤立した文書を作りません。
- 分割した文書から親の索引へ戻れるようにします。
- 本文と根拠を二重にコピーしません。要約＋リンクにします。

## 禁止する分け方

- 行数・バイト数だけを見た機械的な切断。
- 見出し、表、コードブロックの途中での切断。
- 必須の条件、否定条件、例外、失敗した試行を別ページへ追い出す分割。
- 閾値回避だけを目的にした細片化。

## 整理の前に決めること

入力は対象文書、基準の commit、依頼の範囲、リンク・サイズ検査の結果です。利用、構築、検証、調査、実験、履歴・出典に分類し、各主題の本文をどこに置くかを決めます。索引は読者が必要な文書を選ぶための短い説明とし、別の索引へ行くだけの階層を増やしません。

- 現在の決定と、取りやめた計画・当時の仮説を区別します。過去の本文は後の知識で改変せず、冒頭から現在の決定へ案内します。
- 重複候補は代表文に加え、数値、条件、否定、出典、失敗例まで照合します。違いを判断できない場合は削除を止め、相違点を記録します。
- 移動前の見出しと移動先の対応を残します。公開済みの見出しは短い案内として残し、古いリンクも機能することを確かめます。
- 原文の引用と実験 CSV は、文章の整理のためには変更しません。誤りの訂正は元の値・理由・訂正後の根拠を残します。

## 分割の判断順序

1. **棚卸し**: `git ls-files '*.md'` と `python3 .github/scripts/check-doc-size.py` で対象とサイズを把握します。
2. **意味単位の選定**: 各節が「読者と目的」「主題」「手順」「証拠（実験の条件・基準・生データ・失敗）」「参照情報」のどれとして独立して答えられるかを判断します。
3. **既存の主題文書との照合**: 移動先が既に同じ主題を扱っていないか、代表文 2〜4 件で確認します。内容が既に収録されているなら移動せず、要約＋リンクに置き換えます（複製を作らない）。
4. **移動先のサイズ**: 移動先も 40,000 バイトを超えないことを確かめます。超える場合は別の主題文書か、主題として自立する新ファイルを選びます。
5. **移動**: `git mv` または節の抽出で移し、元の位置に短い要約と移動先リンクを残します。公開済みの旧見出しへの参照がある場合、旧位置に短い案内と必要な anchor を残します。
6. **照合**: 移動の前後で、見出し、内部リンク、他文書からの参照、条件、失敗記録、ライセンス・出典が失われていないことを確かめます。

## サイズ検査と例外

- 検査: `python3 .github/scripts/check-doc-size.py`（追跡中の自作 Markdown を UTF-8 バイト数で測定。`vendor/` とシンボリックリンクは対象外）。
- 例外は `.github/doc-size-exceptions.tsv` に `パス<TAB>種別<TAB>許容バイト数<TAB>理由` の 1 行で登録します。種別は `upstream` / `legal` / `generated` / `record`。
- 例外が認められるのは、upstream 原文、法的文書、生成された証拠、記録の完全性を保つため分けられない文書に限ります。パスの広い一括除外は認めません。
- 不要になった例外、存在しないパス、重複、理由なし、許容値の超過は検査が失敗します。長くなったからといって許容値を自動更新しません。
- テスト: `tests/check-doc-size/run.sh`。
- サイズ検査は意味の保存を証明しません。見出し・参照・条件の照合を必ず行います。

## 既存大きい文書の扱い

- 20,000 バイト超の既存文書は、追加・改訂のときに意味単位を再検討します。数値だけを根拠にした一斉分割はしません。
- 索引型の文書（RESEARCH.md など）は、各節を「短い要約＋主題文書へのリンク」に揃え、本文は主題文書側に持たせます。

## 提出前の確認

- [ ] 各主題の本文の置き場が明確で、親索引と戻り先がある
- [ ] 旧見出し・条件・出典・失敗記録を移動前後で照合した
- [ ] 現在の決定と過去の計画を読み分けられる
- [ ] `check-links.py` とそのテスト、サイズ検査、日本語と文字の検査を実行した
- [ ] サイズ検査では分からない意味上の変更と、確認できなかった範囲を報告した

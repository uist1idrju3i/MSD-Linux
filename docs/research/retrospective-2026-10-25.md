| S10 v2 の基準に、T1〜T7 はすべて拒否と書いた | 前回の記録では、T6-truncated-tail と T7-other-signed は受け入れる。基準を記憶から書いた | 期待値は前回の記録の CSV から機械的に写す。ゲストの測定が終わる前に直し、直したことを記録した |
| `remount,rw` の比較を、rebase の前の build で測った | 測った後で、#106（カーネル 6.18.58）のマージ後の main に branch を rebase した。PR の commit は、測った commit と違うものになった | 測定は、PR の base になる commit の上で行う。base が変わったら、build と試験をやり直す |
| S15 の本測定で、条件ごとにホストの負荷が違った | 11.1.2 の条件を、ほかの build と同じ時間帯に走らせた。icount の `sleep` が on なので、仮想時間がホストの実時間の影響を受ける | 比べる条件は、同じ負荷の下で続けて測る。事後に測り直した結果は判定に使わず、分けて書いた |

## 3. 改善の提案

次の提案は、まだどれも実装していません。

1. `test-powerfail.sh` に CSV の出力先の引数を足し、既定では `output/` の下に書く。過去の記録の CSV に行が足されなくなります。
2. dm-verity の case を作る道具（`veritysetup`）を、開発用イメージか host package で用意する。いまは製品の build に含まれず、`make-case.sh` は inittab の検査の後で止まります。
3. icount の測定では、`sleep=off` を選べるようにする。ホストの負荷が仮想時間に効かなくなります。値の意味が変わるので、既定を変える前に、いまの基準値と比べる必要があります。
4. QEMU 11.1.2 の起動の実時間が、11.0.2 の約 8 倍だった原因を調べる（S15 の所見）。CI の時間に効きます。
5. 開発用イメージの QEMU の SHA-256 を image の label に書く（S12 と S15 の記録で、手元の build と CI の binary が一致しなかった）。

# S2 IMX219 カメラの最小構成

- 状態: 完了（QEMU 起動時間の採否基準は未達）
- 日付: 2026-10-19
- 担当: Devin
- 関連: S2 カメラ対応、[起動・カーネル調査](../research/boot-and-kernel.md)、[生データ CSV](2026-10-19-s02-camera.csv)

## 目的と仮説

CM0 で IMX219 の V4L2 raw capture に必要な Unicam と sensor driver を module として有効にします。libcamera、VCHIQ、`bcm2835-isp` は対象外とし、cut-down firmware と GPU メモリー設定を変えません。camera/V4L2 module を必要最小限にすれば、Image の増加と QEMU 相対 ready-marker 時間を採否基準内に抑えられると仮定しました。

## 採否の基準（結果を見る前に書く）

- kernel `Image` の差分: **+65,536 B 以下**
- QEMU 相対 ready-marker の中央値の差分: **+1.0% 以下**
- 生成した module payload がすべて署名済みであること
- `drivers/media/` 以下の module 集合が、`bcm2835-unicam`、`imx219` および両者が必要とする media core (`mc`、`videodev`、`videobuf2-*`、`v4l2-fwnode`、`v4l2-async`、`v4l2-cci` など) の allowlist と一致し、その他の media/video module を含まないこと

## 手順

`BASE_WORKTREE` は基準 commit の checkout、`REPO` は S2 branch の checkout、`OUTPUT_DIR` は Buildroot の `O=` directory、`LOG_DIR` はリポジトリ外のログ保存先です。Buildroot の make は `env -u BASH_ENV` で実行しました。

```sh
BASE_WORKTREE=<基準 commit の checkout>
REPO=<devin/s2-camera の checkout>
OUTPUT_DIR=<Buildroot の O= directory>
LOG_DIR=<リポジトリ外のログ directory>
HOST_DIR="$OUTPUT_DIR/host"
BINARIES_DIR="$OUTPUT_DIR/images"

env -u BASH_ENV make -C "$BASE_WORKTREE/vendor/buildroot" \
  BR2_EXTERNAL="$BASE_WORKTREE" O="$OUTPUT_DIR" msd_cardputerzero_defconfig
env -u BASH_ENV make -C "$OUTPUT_DIR" -j2

env -u BASH_ENV make -C "$REPO/vendor/buildroot" \
  BR2_EXTERNAL="$REPO" O="$OUTPUT_DIR" msd_cardputerzero_defconfig
env -u BASH_ENV make -C "$OUTPUT_DIR" linux-reconfigure
env -u BASH_ENV make -C "$OUTPUT_DIR" -j2

"$REPO/board/cardputerzero/tools/check-kernel-fragment.sh" \
  "$REPO/board/cardputerzero/linux.fragment" "$OUTPUT_DIR/build/linux-custom/.config"
"$REPO/board/cardputerzero/tools/check-modules-dep.sh" "$OUTPUT_DIR/target"
"$REPO/board/cardputerzero/tools/check-dt-overlays.sh" \
  "$HOST_DIR" "$BINARIES_DIR" "$BINARIES_DIR/config.txt"

"$REPO/board/cardputerzero/tools/bench/run-s6-boot-cost.sh" \
  s2-camera "$BINARIES_DIR/sdcard.img" "$BINARIES_DIR/Image" \
  "$BINARIES_DIR/bcm2710-rpi-3-b.dtb" "$LOG_DIR/variant/timing-final" \
  "$LOG_DIR/variant/boot-cost-final.csv"
```

boot runner は `QEMU_ICOUNT=shift=0` と `QEMU_EXTRA_APPEND='initcall_debug printk.time=1 msd.sweep=1'` を子プロセスへ設定します。`test-qemu.sh` は `msd.module-test=usbnet,bcm2835-unicam,imx219` を追加し、3 module すべての成功 marker を確認します。base も同じ runner で測定しました。

artifact の byte 数は `stat` と `gzip -9n Image` で計測しました。boot VFAT の `kernel8.img` は Buildroot host の `mcopy` で抽出しています。host tool の版は `"$HOST_DIR/sbin/mke2fs" -V`、`"$HOST_DIR/bin/mksquashfs" -version`、`"$HOST_DIR/bin/genimage" --version`、`"$HOST_DIR/bin/dtc" --version` の出力から記録しました。

## 計測器の検証

QEMU p5/p6 serial log は `usbnet`、`bcm2835-unicam`、`imx219` の `modprobe` と `lsmod` が成功し、`MSD/Linux ready` に達したことを示します。guest 側 module-check hook が要求した module load を実行し、target module payload 1,051 個すべてに signature marker があることも確認しました。

ready-marker の timestamp は各 serial log と CSV で一致しました。base spread は 0.004378 s、variant spread は 0.002765 s です。3 回としたのは `shift=0` icount の決定性を利用し、観測した run 間 spread が差分 0.150780 s より十分小さいことを確認できたためです。S6 の先行測定でも 3 回の spread は 0.011 s 以下で、比較差 0.083 s より小さいことを確認しています。

新規の camera/V4L2/core module 12 個は `bcm2835-unicam`、`imx219` と必要な media core だけです。残る 15 個（`cec` と `media/rc`）は既存 S7 support として維持しました。したがって新規 camera module の allowlist は満たしますが、camera/core だけを許す global allowlist と解釈した基準には既存 RC/CEC が残ります。`VIDEO_*` の有効 module symbol は `VIDEO_DEV`、`VIDEO_BCM2835_UNICAM`、`VIDEO_IMX219` のみです。

`check-kernel-fragment.sh` と `check-modules-dep.sh` は成功し、signed payload は 1,051/1,051 でした。target に `v4l2-ctl` と `media-ctl` が存在します。`ALSA`、JPEG、libudev、GL/GLU、Qt5、SDL2 image の任意依存は選択されていません。`rootfs.squashfs` の増加は 1,503,232 B です。

post-image の DT checker は active overlay を順に適用し、`sony,imx219` node（`/soc/i2c0mux/i2c@1/imx219@10`）と CSI1 の `okay` を確認しました。一時的に `dtoverlay=does-not-exist` を追加した試験では missing-overlay error で失敗しました。

## 捨てた試行と経緯

- 最初の media build では 36 個の media module ができ、無関係な sensor / video driver が含まれました。明示 disable を追加した後も UVC と Videobuf2 SG/VMALLOC が残り、原因は `USB_CONFIGFS_F_UVC` と `USB_G_WEBCAM` でした。両 parent を無効化して再構成し、最終 variant は 27 個（既存 RC/CEC 15 個と camera/core 12 個）になりました。
- 初回の QEMU 呼び出しでは `OUTPUT_DIR` を渡さず、既定位置に `sdcard.img` が見つからず起動前に失敗しました。再利用中の `O=` を明示して再実行しました。
- `mcopy` を PATH から呼ぶ方法は失敗しました。Buildroot host の `mcopy` を使って boot VFAT の kernel image を採取しました。
- host `kmod` は `-OPENSSL` build のため `modinfo -F signer` の signer field が空で、これだけでは未署名判定になりません。signature marker の全件 scan と QEMU module load を使って確認し直しました。
- Buildroot の post-build log には開発用 update-signing key を release に使わないよう警告があります。これは module signature の検査結果とは別の警告です。

## 結論

`Image` 差分 0 B と全 module signature は基準内です。camera/core の新規 module set は必要最小限でしたが、既存 S7 の RC/CEC module 15 個は維持しています。QEMU ready-marker 中央値は +4.6614% となり、事前設定した +1.0% 基準を満たしませんでした。QEMU 測定では新規 module test が ready marker 前に実行されるため、通常起動だけの差分とは分離できていませんが、結果を基準内とは扱いません。

QEMU は `raspi3b` / Pi 3B device tree を使用し、firmware overlay を適用していません。QEMU では GPIO、camera regulator、aux UART などの peripheral probe error と ioremap warning が記録される一方、両 slot は ready に達して三 module の load test に成功しました。QEMU は CM0 camera pipeline や撮像の検証ではありません。**実機 capture は試していません。**

## 未確認の点

- CM0 camera power-enable GPIO の割当て（GPIO40、GPIO16、M5IOE1 のいずれか）。
- 実機で `media-ctl -p` が示す topology と CSI1 2-lane raw capture。
- Lite 版で IMX219 probe が失敗する場合の実際の kernel message。
- module test を含めない同一条件の QEMU boot time と実機での起動時間。

実機確認時は power GPIO の候補を測定してから設定し、`media-ctl -p` と `v4l2-ctl --stream-mmap` による raw capture を行います。Lite 版に camera がないことによる probe failure は想定内ですが、実機で message を確認します。

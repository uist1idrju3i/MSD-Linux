# kbdの未使用tool削減

- 状態: 現行CI imageの再pack・QEMU比較完了
- 日付: 2026-11-23
- 担当: Devin
- 関連: [kbdの選択肢](../research/component-options/kbd.md)

## 目的と採否の基準

候補1・2を適用済みの現行構成CI imageを変更前とし、loadkeys以外の未使用kbd toolだけを除く。
rootfs通常file合計とSquashFSの両方が1 byte以上減り、loadkeys・keymap・他の残存fileの内容が不変なら容量面で採用する。
変更前後のA/B全4 bootでkeymap読込みの終了0、ready/login、QMP quit・reap・終了0を要求する。
全4 bootのmodule名・サイズ・依存・状態が一致することも要求する。参照数・addressは比較しない。
容量削減を起動時間の短縮と扱わず、QEMUのkeymap読込みをM5実機のkeyboard動作と扱わない。

## 失敗とCSVの派生

最初の準備は、unsquashfsのversion表示が終了1を返すため止まった。表示内容も照合して、このCLIのversion応答だけを許可した。
次の準備はvar/wwwの所有者変更警告で終了2となり、pack前に止まった。
containerはcap-drop ALLで、展開先の所有者変更は保証しない。再packはall-rootで正規化するため、このpathの所有者警告だけを記録して許可した。
同じ終了2でも、別のerror・failed・cannot・fatalが出た場合は拒否する。通常の展開の終了1も拒否する。
両方とも測定前の失敗として残し、成功に書き換えていない。

[公開CSV](2026-11-23-kbd-tools.csv)は標準8列の44行である。
2つの準備失敗行、2回目の未実施21行、成功した測定の21行を並べた。
成功の21行はmeasured/results.csvの写し。未実施21行はretry/results.csvの値・valid・noteを保ち、IDだけkbd-r1からkbd-preflightへ変えて重複を避けた。
準備の終了値は取得した実行出力とbuild.logから転記した。valid=trueは21行で、期待した負の対照の失敗も含む。
生の2 CSV・plan・JSON・serial・QMP記録・失敗出力は[証拠archive](2026-11-23-kbd-tools.tar.gz)にある。

## 再実行

比較元には、候補1・2適用済みでkbdをまだ削っていない上記CI artifactを使う。削減後のimageは拒否する。
同じproducer commitをbuildし直す場合も、生成物のhash差は別条件として残す。
取得したZIPのdigest一致を先に要求し、毎回新しい空の出力先を指定する。
現行の測定器は実行ごとにUUIDを作り、run_idをkbd-UUID-条件-指標とする。
results.jsonのrun_prefixとplan.jsonで実行を対応づける。失敗後の再試行でもUUIDを使い回さない。
初回の公開CSVにあるkbd-r1・kbd-preflightなどのIDは当時の値として保持する。

```sh
printf '%s  %s\n' \
  51b73de7ea6da9d8b0262e553dfb11a9c69e15b1762b23e6de9a03bdeb2ffc7c \
  output-kbd-r1/build.zip | sha256sum -c - && \
docker/msd-dev python3 board/cardputerzero/tools/bench/kbd.py \
  --artifact /work/output-kbd-r1/artifact \
  --host-tools /work/output-integrity/host \
  --config /work/output-kbd-config/.config \
  --out /work/output-kbd-replay
```

artifactはZIP内のimagesを展開したdirectory、host-toolsは同じSquashFS tool版を持つBuildroot host directoryである。
configはこのbranchのdefconfigを正規化して作る。元の測定用configとbinary hashはarchiveで照合する。
出力先が既存なら停止する。測定器はtest-boot.shとtest-ab.shを使い、各試行のSDは使い捨てcopyとする。

## Review後の測定器修正

初回の記録と生証拠は変更していない。以後の実行ではserial-allowlist.txtも入力とし、未commit差分を拒否してhashを保存する。
負の対照は終了1だけで合格にせず、ready・loginへの到達、S04のloadkeys終了1、keymap失敗logを要求する。
さらにboot-test.pyがready後のserial検査で失敗したことと、QMP quit・reap・QEMU終了0を要求する。
timeout（終了124）、ready前の停止、QMP停止失敗は不合格とする。timeout fixtureもhost回帰試験に含めた。
これらは測定器の判定・追跡の修正であり、新しい容量測定や製品の変更ではない。

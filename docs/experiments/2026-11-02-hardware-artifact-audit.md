## 目的・条件・判定

公式回路図とソースだけでなく、配布に使う生成物にもDTBO、module、firmware、keymap、権限が反映されたか確かめる。承認済みのハードウェア監査に従う静的照合で、起動性能・実機動作の採否試験ではない。構築済みの同じbyte列を調べるため各試行1回とし、5回の性能比較には転用しない。ccache、cold/warm、ビルド再構成の比較は行わない。

判定条件は生成元の固定、入力hashの保存、指定overlayの合成成功、cameraとCSIのstatus、moduleとfirmwareの収録、所有者・modeの確認である。実機probe、GPIO波形、電断保持時間、無線、USB、LCDやcameraの動作は対象外とする。

## 再確認の手順

`gh`、Docker、xz、util-linux、squashfs-tools、kmodが必要である。既存出力へ上書きしない。以下はこのCI生成物を検査する手順であり、新規ビルドではない。成果物が保存期限を過ぎた場合は取得できない。新しいrunの結果をこのrunの検証結果に置き換えない。

```sh
AUDIT_DIR="$PWD/output-artifact-audit"
test ! -e "$AUDIT_DIR" || exit 1
mkdir "$AUDIT_DIR"
gh run download 41477653658 --repo uist1idrju3i/MSD-Linux --dir "$AUDIT_DIR"
IMG="$AUDIT_DIR/msd-cardputerzero-build/images/sdcard.img"
xz --decompress --keep "$IMG.xz"
sha256sum "$IMG.xz" "$IMG"
sfdisk --json "$IMG"

# 固定OCI image。タグだけに依存しない。
DEV=ghcr.io/uist1idrju3i/msd-dev@sha256:c5beb4973cad6bef273fd0efc51deb89e334de5f5b1700de2f41980410d65d77
docker run --rm --network none --read-only --entrypoint /usr/bin/dtc "$DEV" --version
mkdir "$AUDIT_DIR/boot-a"
docker run --rm --network none --read-only --cap-drop ALL \
  --security-opt no-new-privileges --user "$(id -u):$(id -g)" \
  --mount "type=bind,src=$AUDIT_DIR,dst=/evidence" \
  --entrypoint /usr/bin/mcopy "$DEV" -s \
  -i /evidence/msd-cardputerzero-build/images/sdcard.img@@20971520 \
  ::config.txt ::bcm2710-rpi-cm0.dtb ::overlays /evidence/boot-a

# 実行した版の検査scriptを使う。現在のcheckoutの変更を混ぜない。
git show 84ca145032216b696a8944d54b4f820edc1ac565:board/cardputerzero/tools/check-dt-overlays.sh \
  > "$AUDIT_DIR/check-dt-overlays.sh"
chmod +x "$AUDIT_DIR/check-dt-overlays.sh"
docker run --rm --network none --read-only --cap-drop ALL \
  --security-opt no-new-privileges --user "$(id -u):$(id -g)" \
  --mount "type=bind,src=$AUDIT_DIR,dst=/evidence" \
  --entrypoint /evidence/check-dt-overlays.sh "$DEV" \
  /usr /evidence/boot-a /evidence/boot-a/config.txt

# 元image内の数値UID/GIDとmodeを見る。抽出先の所有者とは区別する。
unsquashfs -lln -o 159383552 "$IMG" etc lib/modules lib/firmware usr/share/keymaps
unsquashfs -d "$AUDIT_DIR/root-a" -o 159383552 "$IMG" \
  etc lib/modules lib/firmware usr/share/keymaps
modinfo "$AUDIT_DIR/root-a/lib/modules/6.18.59-v8/updates/m5ioe1.ko.xz"
grep -E 'CONFIG_(MODULE_SIG|VIDEO_IMX219|VIDEO_BCM2835_UNICAM|USB_NET_SR|RTC_DRV_DS1307|PREEMPT)' \
  "$AUDIT_DIR/msd-cardputerzero-build/build/linux-custom/.config"
```

上記offsetは `sfdisk` で得た512-byte sectorの開始値から計算した。p2は40,960 × 512 = 20,971,520、p5は311,296 × 512 = 159,383,552である。別のimageへ流用しない。p1はbootsel、p2/p3はboot A/B、p4はextended、p5/p6はrootfs A/B、p7はdataである。

## 確認した内容

### DTとモジュール

- 実物のCM0 DTBへv5、BQ27220、BMI270/BMM150、IMX219を順に適用し、IMX219 `/soc/i2c0mux/i2c@1/imx219@10` とCSI1の `status=okay` を確認した。sensor側とCSI側の `data-lanes` はともに `<1 2>`。物理4 lane対応をLinuxの既定4 lane設定と混同しない。
- I2CのM5IOE1 `0x4f`、TCA8418 `0x34`、ES8389 compatibleの `everest,es8390` / `0x10`、RTC `0x32`、BMI270 `0x68`、BQ27220 `0x55` を読み取った。BMM150はrootのnodeからBMI270への参照を持つ。`rest-gpios` も生成物に残る。propertyの存在だけでdriverが制御したとはしない。
- rootfsの `updates/` に16 M5 modules、LCDとBMI270の2 firmware、TCA8418 keymapを確認した。moduleの署名者表示は `Build time autogenerated kernel key`。署名metadataの読取りは全moduleの暗号検証や実機probeとは別である。
- 最終 `.config` はUnicam、IMX219、SR9700、SR9800、DM9601、RX8130用DS1307、BRCMFMAC、HCIUARTをmoduleで有効化。DWCOTGとDWC2は組込み、IR受信とPWM送信はmoduleで、IR overlayは未選択。BlueZの選択はない。
- 最終設定とvermagicにはPREEMPT_RTが現れる。PREEMPT_RTの記載がある現行fragmentと一致する。過去の実験本文にある「現行PREEMPT維持」を現在の生成物の証拠にはしない。

DT合成はfirmwareの全 `dtparam` 処理、実際のdriver bind、最終runtime DTを再現するものではない。暗黙の `status` がないnodeもあり、その全てをこの検査でokayとassertしたとは扱わない。

### 所有者・権限・起動

SquashFSの数値一覧では、16 modules、2 firmware、keymapはUID/GID `0/0`、mode `0644`。init scriptsは `0/0`、`0755`、mdev設定とinittabは `0/0`、`0644`。抽出先ファイルをVM利用者が所有することは、imageの所有者が変わったことを意味しない。

生成mdev設定にはinputの `root:root 640`、audioの `root:audio 660`、keyboardと電源通知のhook、modaliasのmodprobeがある。inittabはconsoleへのgettyをrespawnし、自動root loginの指定はない。これだけで非root利用者の全機能が使えるとは判断しない。

同runのQEMU A/B serial本文では、p5/p6のSquashFS RO、p7のext4、readyとlogin prompt、usbnet / Unicam / IMX219のmodprobe確認を読んだ。電源異常smokeでは通知、SysRq-U、dataのRO再mountを確認した。`cannot resolve /boot for sync: -2` は `/boot` 未mountの試験条件に残る。QEMUの機能範囲を超えるfirmware、LCD、keyboard、実電断を確認したとは扱わない。

## 失敗試行と計測器の照合

| 試行 | ツール・方法 | 終了状態 | 読み方 |
|---|---|---|---|
| host-all | DTC 1.6.1、4 overlayを一括適用 | 失敗、IMX219で `FDT_ERR_NOTFOUND` | 旧host toolでは確認不能。製品不具合の根拠にしない |
| host-script | DTC 1.6.1、既存checkerの逐次適用 | 同じ失敗 | 引数の一括指定だけの問題ではない |
| dev-script | DTC 1.7.2、既存checkerの逐次適用 | 成功、IMX219とCSI1 okay | CIで使う版に合わせて確認 |
| dev-all | DTC 1.7.2、同じ4 overlayを一括適用 | 成功、JSONのnodeを取得 | 同一入力の二つの適用方法で照合。性能A/A試験ではない |

入力fileは同一hashで、古いツールだけが失敗した。原因commitまでのDTC解析はしていない。ツールを替えた成功で失敗試行を消さず、GPIOやoverlayへ根拠のない修正も加えない。

# 起動・カーネル文書の配置と本文保存の照合

[実験一覧](README.md) / [配置の判断](../research/document-map.md) / [調査の索引](../../RESEARCH.md)

## 目的と基準

旧文書の案内だけの階層をなくし、起動・測定・カーネルの本文を主題別に配置します。製品設定・更新形式・公開バージョン・ログイン方式は変えません。基準commitは`3cbf71669f0eb5f297fb946896dd595debce50e0`です。

採否の条件は、7文書の移動と旧文書の§22の保存により、技術的本文の数値・条件・否定・URLが失われないことです。題名、案内、冒頭の定型文は区別し、本文は相対リンクを移動先に換算して完全一致を求めます。CSVなど過去の測定値は変更しません。決定的な照合を5回行い、改変した対照を一致と判定しないことも確認します。これは性能測定ではないので、時間の中央値や改善率は出しません。

## 変更した範囲

移動先と読む目的は[配置表](../research/document-map.md#起動カーネル文書の移動対応)に記載しています。旧文書に残っていたGPIO6/PYG6、電断、PLP、dm-verity、watchdog、スーパーキャパシタ等の表は[設計論点](../research/boot/design-notes.md)に保存しました。旧ファイルや旧anchorを維持するための案内は残しません。

カーネルの生成方針は、現行コードを参照する説明と、当時の方針メモを見出しで分けました。`CONFIG_PREEMPT_RT=y`の指定を現行fragmentで確認し、「PREEMPT_RTは対象外」という古いメモを現行設定として読まないようにしました。過去のAPI・起動可否の未確認事項を、今回解消したとは扱いません。

RESEARCHとDeepWikiの参照、他文書の相対リンクを更新しました。旧入口を参照していたRX8130の行は回路監査へ、alias unmapやPREEMPTの行はカーネル比較へ、更新時の終点は測定手法へ振り分けています。DeepWiki全体・README全体・公開サイトの再設計や、他分野の本文整理が終わったという意味ではありません。

## 再実行

環境はLinux `6.8.0-1061-aws`、x86_64、Python `3.12.13`、Git `2.34.1`です。製品buildやQEMUはこの静的照合に使っていません。

基準commitを参照できるcloneで、[照合スクリプト](2026-11-02-boot-document-layout.py)を実行します。出力先は既存ファイルを上書きしないため、毎回新しい名前にします。

```sh
python3 docs/experiments/2026-11-02-boot-document-layout.py \
  --base 3cbf71669f0eb5f297fb946896dd595debce50e0 \
  --output boot-document-layout-new.csv
```

スクリプトは元本文から題名・案内の定型文だけを除き、相対リンクの換算後に本文全体を照合します。firmware文書の技術的な前書きも対象です。旧§22の表は、行・否定・値・URLを含めて比較します。本文を要約したり、数値だけを抽出したりする検査ではありません。追加した現行設定の説明は、別にコードと読み比べています。

## 結果と失敗した試行

[全結果CSV](2026-11-02-boot-document-layout.csv)に、各回の本文bytes、比較対象双方のSHA-256、期待する結果、判定を保存しました。8本文を5回照合した40件は一致しました。GPIO番号の変更、表の行の削除、firmwareの技術的前書きの削除、出典URLの変更の4対照は、いずれも不一致でした。

初回の移動処理では、最初の見出しまでを案内とみなしたため、firmware文書の技術的前書きも落としていました。変更前の保存内容から復旧し、前書きを含む完全一致の対象に直しました。この欠落を含む版はコミットしていません。初回のリンク検査は、新規ファイルと削除をindexへ反映する前だったため2件失敗し、対象をstageした後は成功しました。誤って初回を成功としたり、検査を単にflakyとしたりはしません。

リンク・文字・文書サイズの検査は復旧後に成功しました。文字集合の既存警告9件と、20,000バイトを超える文書の警告は残っています。大きな文書の分割と本文の重複解消は、全体整理の後続作業です。文字・リンクの検査成功を全文精読や日本語の意味の認定とはしません。

## 限界

保存の照合は、保存した文章の主張を正しいと認定するものではありません。既存のQEMU・実機・第三者の結果を再実行した検証でもありません。代替構成のbuild・性能測定、実機でのfirmware・周辺機能・更新は、本リポジトリではこの変更の確認として試していません。現行設定の根拠、過去の調査時点、未確認範囲は、それぞれの本文で区別します。

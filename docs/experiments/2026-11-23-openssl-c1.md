# OpenSSL C1の製品適用と外部TLS接続

- 状態: host接続確認完了・製品buildと実機は未確認
- 日付: 2026-11-23
- 担当: Devin
- 関連: [既存QEMU設定比較](2026-11-18-openssl-cnf.md)、[OpenSSL調査](../research/component-options/openssl-minimal.md)

## 目的と仮説

利用者が選んだC1（TLS最低版1.2・SECLEVEL=2）だけを製品へ適用する。
C2のAEAD限定は採用しない。既存CA/CSR節、DEFAULT groupsとTLS 1.3は維持する。
既存設定の`openssl_conf`と`config_diagnostics=1`は変更せず、default providerの明示とTLS方針を追加する。
設定の読込みをapplicationが上書きする場合まで、通信を強制制限する機能とは扱わない。

## 採否の基準

結果を見る前に次を固定する。以前のendpoint調査と同じhost上の`openssl s_client`を使い、
GitHub関連5 hostと既存比較先muromi.moeのTLS 1.2/1.3で接続・証明書chain・hostname検証を試す。
各組合せは機能確認として1回とし、性能の結論には使わない。
候補時刻serverの`time.cloudflare.com:4460`もTLS 1.3とALPN `ntske/1`で試す。
全13接続の終了0、所定protocol、verification成功を要求する。
通常のNTPはTLSを使わず、この追加試験もNTS-KEのTLS接続だけで、NTP同期全体を検証しない。
github.comに誤ったhostnameを指定する負対照は非0、C0とのA/Aは同じ成否を要求する。
失敗もCSVとraw logに残し、timeoutは成功に混ぜない。

## 計測器の検証

同一C0設定によるgithub.comのTLS 1.3接続は2回とも終了0で、verification成功。
C1で`-verify_hostname wrong.invalid`を指定した対照は`hostname mismatch`で終了1となった。
成功文字列があっても非0・timeout・protocol違い・verification欠損なら不合格とするhost testを加えた。

## 既に存在した設定

| 項目 | 根拠と扱い |
|---|---|
| config初期化・診断 | 入力cnfに`openssl_conf = openssl_init`と`config_diagnostics = 1`が存在。変更しない |
| SECLEVEL | OpenSSL 3.5.9の`include/openssl/tls1.h`は`OPENSSL_TLS_SECURITY_LEVEL`未指定時に2。C1ではCipherStringにも2を明記する |
| TLS 1.0/1.1の拒否 | 以前のQEMUでC0も拒否済み。新たな拒否効果とは主張しない |
| default provider | 入力は暗黙の有効化。C1と同じく明示activateを追加する。legacyの自動loadは追加しない |
| CA/CSR・groups | 既存節を保持し、Groups・Ciphersuites・SignatureAlgorithmsの固定を追加しない |

適用処理は既に同値ならfileを書き直さない。空・欠損・競合する設定はbuildを失敗させる。
製品ではpost-buildからhost Python 3で実行し、測定用runnerはimageへ入れない。

## 結果と未確認事項

16 case全てが期待する成否となった。[CSV](2026-11-23-openssl-c1.csv)に全終了値とlog hashを保存した。
掲載CSVは原本のCRLFをLFへ変換しただけで、値は変更していない。archive内のCSVはCRLFの原本を保持する。

| 接続先 | TLS 1.2 | TLS 1.3 |
|---|---|---|
| github.com / api.github.com / codeload.github.com | 各終了0・検証成功 | 各終了0・検証成功 |
| objects.githubusercontent.com / release-assets.githubusercontent.com | 各終了0・検証成功 | 各終了0・検証成功 |
| muromi.moe（以前からの比較先） | 終了0・検証成功 | 終了0・検証成功 |
| time.cloudflare.com:4460（時刻合わせの候補） | 対象外 | 終了0・検証成功 |

時刻合わせは[既存の候補](../research/security/history/network.md#9-時刻合わせ-timecloudflarecomnts-要検討)を使った。
通常のNTPはUDPであり、TLS最低版の影響はない。現行製品はchrony/NTS未導入である。
NTS-KEのTLSに成功しただけで、ALPN選択、NTS record交換・cookie発行、UDPのNTP同期を完了した意味ではない。

接続先とのC1互換はhostのCA storeと時計で確認できた。ただし入力artifactは
`BR2_PACKAGE_CA_CERTIFICATES`が未選択で、製品のCA配布・初期時刻は別途必要である。
この変更でCA packageや時刻daemonを追加せず、証明書検証も無効化しない。
GitHubのHTTP redirect・実asset取得・Rangeは測っておらず、[RAUC PoC](2026-11-23-rauc-streaming-poc.md)の残件を閉じない。

捨てた試行・timeoutは0。全caseを初回の出力先r1へ保存した。
利用者判断に従いC1だけを採用する。C2のAEAD限定は採用しない。
実機の通信・LCD・SD write・boot時間と、製品全体のA/B起動はこのhost試験では確認しない。
設定はbuild時に作るRO rootのfileだけであり、製品の画面や実行時の永続writeは追加しない。

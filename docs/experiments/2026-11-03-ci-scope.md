# CIの差分判定の再実行と実行履歴の観察

- 状態: 固定したpath判定の照合済み。性能最適化は未実施。
- 日付: 2026-11-03 UTC
- 担当: Devin
- 関連: [調査と改善候補](../research/operations/ci-build-scope-and-performance.md)、[実験の一覧](README.md)

## 目的と判定条件

文書差分で製品buildが起動する理由と、既存の並列化・cacheの使われ方を調べます。事前の計画では、固定workflow・PR累積差分・実際のjob/step結論を対応づけ、5件の履歴観察を性能実験と混同しないこと、raw logを公開せず必要な列だけを抽出することを条件としました。新しい製品build、QEMU、実機の反復は行いません。

path判定は、文書がfalse、製品入力・署名CLIテスト・build workflow変更・文書と署名CLIの混在がtrueになることを照合します。固定PR全体もtrueになること、意図的に除外規則を広げると不一致が出ることを確認します。性能の採否閾値は置きません。markerの対照は、後述する初回抽出の誤りを受けて追加しました。

## 再実行

checkoutの履歴に上記の2 commitと親があることを先に確かめます。浅いcloneでは必要な履歴を取得します。`run-r01`は未使用の相対pathの例です。下記は既存runの読み出しであり、CIを新規起動する操作ではありません。

```sh
python3 docs/experiments/2026-11-03-ci-scope.py \
  --ref 5d5b275f27da0cf2de6402eeb21b36fb9095a02a \
  --pr-ref 20a80264d65647e933e553cdc33c8a61f0549050 \
  --output-dir run-r01 \
  --collect-run 41548215940 \
  --collect-run 41547703403 \
  --collect-run 41547627611 \
  --collect-run 41540889739 \
  --collect-run 41528679681
```

通信せずpath/markerだけ再実行する場合は`--collect-run`を全て省略します。scriptはGitHub APIからrun metadata、job metadata、job logを取得し、jobが100件を超える時は不完全な集計を作らず停止します。ログ取得失敗は`download-failed`、skipで取得しない場合は`not-requested-skipped`と分けます。今回、対象の実行jobのログ取得失敗はありません。

| 記録 | 内容 | 判定 |

初回CSVは削除・上書きしませんでした。job logには実行command自体もechoされるため、一般的な文字列の出現は処理が実行された証拠になりません。修正時はscriptの終了を待ち、別出力先で再取得しました。負の対照は、echoのみなら`not-observed`、実出力が相反すれば`ambiguous`にすることも確かめています。

固定した開発OCIでもPythonの構文検査と117行の判定を実行し、host側のCSVとbyte単位で一致しました。OCI内のBashは5.2.37、hostは5.1.16です。image IDと確認ログのSHA-256はmetadataにあります。これは判定scriptの照合であり、OCIや製品imageの再構築・認証ではありません。

提出前にはリンク・文字・文書サイズ・skill・siteの検査と各検査器の回帰、差分書式、固定OCIのactionlintとzizmorの[13検査](2026-11-03-ci-local-checks.csv)も終了値0でした。日本語7文書はyomiyasuのrun/verifyを実行し、追加した数値と否定条件を原資料と照合しました。

履歴の152行はstatus、skip、開始・終了、時間、ensure状態、取得状態を含めて照合しました。success markerだけでなく対象jobのstepとjob conclusion、cache復元・保存、後続の包装・終了まで読みました。大きなraw logはprivateに保持し、公開CSVには選択した列だけを転記してSHA-256を照合しました。期限後にGitHubのログが取得できなくなった場合、CSVの再集計と生ログの再確認は区別します。

## 結論と未確認

PR全体に含まれる署名CLIテストが製品buildを要求すること、純粋な文書整理なら製品buildを省略することを、固定case・PR差分・実行履歴で対応づけました。署名CLI runnerは現在のworkflowから呼ばれていないため、軽量分類へ移すなら明示的なCI組込みも必要です。

cacheは復元・保存まで動いていますが、OCI未公開時のlocal buildが複数jobに発生します。既存cacheの長期hit率、転送・evictionの費用、layer共有、suite分割、native ARM製品buildの採否は未測定です。path判定以外のevent/fetch/diff失敗分岐はソース確認のみです。製品設定・workflow・Brotli・公開ゲートは変えていません。実機結果や新しいQEMU結果は含みません。

## 目的と、先に定めた採否の基準

4文書の配置、書き込みpolicy、FS候補、電断、A/B、復旧を読む目的で分け、本文の全範囲を保存することを確かめます。旧ファイルや旧anchorの互換stubは残しません。現行の操作と最新の比較は既存の正本へ案内し、過去の「現行」「未着手」や試行の失敗を現在の状態へ書き換えません。

採否は、タイトルを除く4原文の全範囲を11ブロックが隙間・重なりなく覆うこと、全ブロックを移動先で照合できること、基準にあるCSV全件が同一であることを5回確認し、4種の改変を全て拒否することです。文書の照合なので所要時間・性能の中央値は求めません。表・コード・条件・否定・失敗記録の途中では分けません。

## 手順と再実行

[runner](2026-11-02-storage-document-layout.py)は基準のgit objectと作業treeを読みます。出力は上書きを拒否するため、未使用の名前を指定します。

```sh
python3 docs/experiments/2026-11-02-storage-document-layout.py \
  --base 55ffde1e8219207c73d1fa1d6c7d2728cf3949a3 \
  --output storage-layout-recheck.csv
```

タイトルは読者の目的に合わせて変更し、新しい案内を冒頭に加えました。原本文の保存照合では、それらを元の本文に含めません。4文書のタイトル以降を連続する範囲へ分け、全範囲が一度ずつ対象になっていることを別に検査します。リンクを移動後の参照先へ換算した11本文を丸ごと照合するため、表の行だけ、数値だけを拾う検査ではありません。

数値の32,769と`align = 4M`、read-only policyと通常のRW mount、S17の当初計画と後のエラー注入、A/Bの当時の比較と現行操作を冒頭の説明で区別しました。K/P/S17のURL・逐語抜粋・適用範囲の表は1か所に保持し、参照する本文から直接案内しています。

## 計測器の検証と初回の失敗

初回の[結果CSV](2026-11-02-storage-document-layout-first.csv)は5回の本文保存と3種の改変対照に成功し、配置数値の改変対照だけ失敗しました。最初の`32,769`を置き換えたため、元の表ではなく、新たに加えた案内文を変えていました。案内文は原本文の照合対象ではないので、runnerが異常としなかったことを記録します。

元の表の`| p2 | 32,769 |`を指定して置き換えるように対照を直しました。実行が終わってから修正し、初回CSVを上書きせず、[再検査CSV](2026-11-02-storage-document-layout-v2.csv)へ別保存しています。初回は9行中1失敗、再検査は9行全て成功です。

| 改変対照 | 変更する元の条件 | 期待 |
|---|---|---|
| partition開始位置 | p2の32,769を32,768へ変更 | 本文の不一致として拒否 |
| 小さいファイルの測定 | 1,110,016 byteを1,110,015へ変更 | 本文の不一致として拒否 |
| S17の権限条件 | `host root 不要`を`host root 必要`へ変更 | 本文の不一致として拒否 |
| watchdogの失敗 | v1の観測窓不足・基準未達を成功へ変更 | 本文の不一致として拒否 |

## 現時点の結果と限界

本文11ブロック・原文4件の全範囲の保存とCSV59件の同一性を確認し、5回の保存照合と4改変対照は通りました。全列と終了状態を読んでおり、初回の対照失敗を成功へ混ぜていません。

この結果は、移動本文の保存を確認したもので、新しい案内文が正確かどうか、過去の数値が正しいかどうかを単独では保証しません。コードとの照合、主題ごとの読み直し、参照・文字・サイズ・推敲の検査は別に実施します。過去のS3/S10/S11/S17の再実行、製品の新しいbuild・QEMU・実機確認を行ったとはしません。

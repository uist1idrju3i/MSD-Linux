# S13: コンパイラー最適化オプションの比較（-O2 / -Os / LTO）

- 日付: 2026-10-30
- 実施環境: 開発用コンテナ（msd-dev:local）、QEMU 11.1.2、icount `shift=0,sleep=off`
- 目的: userspace の最適化フラグが起動時間とイメージサイズに与える影響を測る

## 方法

同一リビジョン（main `fc87b73` 系、PREEMPT_RT + FTRACE off + squashfs -sort/レベル22 を含む）の defconfig に、次だけを追加して 3 本をビルドした。

| バリアント | 変更 | 出力ツリー |
|---|---|---|
| -O2（基準） | なし（`BR2_OPTIMIZE_2=y`） | output2 |
| -Os | `BR2_OPTIMIZE_S=y` | output3 |
| -O2+LTO | `BR2_ENABLE_LTO=y` | output4 |

## 結果

| バリアント | rootfs.squashfs | 対 -O2 | QEMU 起動 |
|---|---:|---:|---|
| -O2 | 28,770,304 B | - | `MSD/Linux ready` 到達 |
| -Os | 22,392,832 B | -22.2% | `ready` 到達、root マウント 0.74s |
| -O2+LTO | 23,764,992 B | -17.4% | `ready` 到達、root マウント 1.85s |

- 起動時間の差（ゲスト時計、n=1）はノイズ範囲内。-Os・LTO とも機能回帰は見られない（ext4 resize、ready バナー、msd-hwinfo 正常）。
- カーネル Image は -Os/-O2+LTO とも 26.5〜21.1 MB 帯（カーネル自体は `TARGET_OPTIMIZATION` の対象外。差は fragment の FTRACE 行の有無による）。
- 注意: output4 のビルドは #135 マージ前のワーキングツリーで開始したため、そのカーネルは FTRACE=y（Image 26.5MB）。userspace の LTO 効果の測定には影響しないが、厳密な同構成比較ではない。

## 結論

- -Os は squashfs で -22% と大きな削減。LTO(-O2) は -17%。両方を組み合わせた場合（`BR2_OPTIMIZE_S=y` + `BR2_ENABLE_LTO=y`）は別途測定が必要。
- 採用判断: -Os（+LTO）は安定性リスクが小さい割にイメージが大きく縮む。SquashFS 読み込み量が減れば実機の起動 I/O も短縮する見込み（効果は実機依存）。
- 次の一手: `-Os + LTO` の組み合わせを製品候補としてビルドし、QEMU 回帰を通るか確認したうえで defconfig へ採用するか判断する。

## 再現手順

1. `output3`: `make -C vendor/buildroot BR2_EXTERNAL=$PWD O=$PWD/output3 msd_cardputerzero_defconfig` → `.config` に `BR2_OPTIMIZE_S=y` を追記して `make olddefconfig` → `make -C output3`
2. `output4`: 同様に `BR2_ENABLE_LTO=y` を追記してビルド
3. QEMU: `KERNEL_IMAGE=/work/outputN/images/Image QEMU_ICOUNT='shift=0,sleep=off' docker/msd-dev board/cardputerzero/qemu/run-qemu.sh outputN/images/sdcard.img`
